两层设计

工程师让助手修复浮标解析器，程序端又希望把它嵌入夜间校验流水线。前者需要终端交互、进度显示和人工纠偏，后者只要可控输入、事件与结果。如果循环直接依赖某个终端组件，两种调用方式就很难复用。Pi 的学习材料把模型与工具的推进机制、会话产品逻辑和显示界面分开，便于追踪这些边界。

packages/agent 提供核心循环及状态封装，packages/ai 适配模型消息，packages/coding-agent 组织编码助手会话和多种入口，packages/tui 承担终端显示。树形会话的持久化主要在 coding-agent 的 SessionManager 一侧，不应因为它是重要底层机制就归入所有 Core 接口。

本章以 13-pi-agent/ 的学习快照说明对象职责。Pi 会继续演进，开箱能力、审批接口和压缩触发点可能与新安装版本不同。当前文档也提醒扩展运行在 Pi 进程内，工具继承操作系统权限。把能力做成扩展是复用选择，不等于自动获得安全沙箱。

Pi Core

Agent 持有当前消息、队列及取消状态，循环接收这些信息来推进模型与工具。区分“循环函数自身不拥有长期产品状态”和“整个 Agent 完全无状态”，后者显然不成立。工具写出的文件又在会话之外，需单独管理版本与恢复。

调用栈与队列

沿调用栈阅读可以避免把一次 API 调用和整个用户任务混为一谈。用户提交一条修复请求后，Agent 可能读文件、运行测试、修补代码，再调用模型形成下一步。产品层还可能处理压缩和可重试故障，最终稳定下来才算这一轮用户工作结束。

对象或函数持有或使用的内容不该假定的能力
runLoop当次消息、工具及模型配置不自己管理所有会话文件和终端状态
Agent运行状态、transcript、队列和 abort不自动回滚工具副作用
AgentSession输入处理、持久会话与产品策略不是一套另起炉灶的模型循环
源码阅读用的路径图
任务：修复温度字段的缺测解析
入口 → AgentSession.prompt
     → 展开输入、准备当前上下文
     → Agent.prompt
       → 核心循环：模型响应 / 工具批次 / 队列检查
     → 产品层收尾：需要重试或压缩时继续处理
最终：任务结束或明确返回失败 / 取消状态

同一 Agent 的运行需要串行化，不能同时让两个 activeRun 修改一份 transcript。中途补充“不要改原始记录”应走 steering，在相应轮或工具边界进入；“做完后再汇总差异”可放 follow-up，等当前工作结束再处理。[1] 键位只是入口绑定，学习快照常用 Enter 与 Alt+Enter 区分，实际安装请看当前快捷键和终端支持，不能断言永久写死。

纠偏不是即时撤销。若写文件工具已经执行，新消息只能约束后续动作；要恢复文件还需实际补偿或版本管理。若产品层重试一次模型请求，也不表示已执行的外部发送可以再做一次。

事件与落盘

事件既驱动显示，也触发持久化与扩展。学习快照里 Core 发事件，Agent 先更新状态，再通知监听者；Interactive 会处理扩展和会话订阅。某个事件已经显示到屏幕，不等于最终消息已完整持久化。

教学事件顺序
模型开始响应
  → 文本增量：界面可显示半句话
  → 工具调用开始 / 更新 / 结束
  → 消息结束：完整消息可追加到会话
  → 会话事件：界面重绘、外部订阅消费

控制监听：可能被 await，能延迟或影响推进
显示监听：通常不应成为模型循环的慢依赖

检查事件处理时，重点看哪些回调被等待、哪些仅通知，以及异常如何传播。需要阻止写原始观测库的扩展应处在明确控制点，不能只订阅事后工具结束事件。等待型回调慢了会直接延长请求，通知型显示也不能假设可以任意抛错。[2]

JSONL 方便逐条追加和解析。进程突然停止时，末行可能不完整，需要识别而不是把整份会话当作损坏；但“每行独立”不自动提供落盘刷写、事务或文件锁。查看 message_end 附近的写入顺序，可以判断刚才屏幕上的半段回复在恢复后是否仍存在。

会话是一棵树

工程师先尝试把空字符串解析成 0，随后发现这样会把缺测当成真实零值，于是回到旧节点，另试返回 null。树结构可以保留两种讨论，不必把错误尝试整段抹掉。每条树记录的 id 与 parentId 定义关系，当前 leaf 决定活跃路径。

新教学会话树
R  明确缺测需求
└─ S  阅读解析器
   ├─ Z  方案：空值转零
   │  └─ Z2  测试发现误标
   └─ N  方案：空值保留 null
      └─ N2  检查缺测用例
当前叶为 N2，发送给模型的是 R / S / N / N2 的有效上下文。

/tree 在当前文件内导航，/fork 把较早位置复制成新会话，/clone 则复制活跃分支。文件保存的全部分支不会无条件送给模型，切枝时若启用离开分支摘要，则可能有选择地带回相关信息。

分支只管理对话历史。Z 分支若已经把解析器写成转零，切到 N 分支不会自动恢复文件。应在隔离练习目录比较真实文件状态，或用版本控制明确切换代码。树形对话类似版本探索，但不是文件系统事务，更不代表撤回已经发出的报告。

提示词是一层一层叠的

提示来自多个资源，而非一段写死的文字。默认提示定义基本工作方式，追加系统文件补充全局约束，项目上下文文件描述仓库约定，技能目录只列可用能力简介，工作目录与日期提供运行环境。不同层级的加载优先级与路径应以所研究版本的资源加载逻辑为准。

学习快照区分 SYSTEM.md 的替换与 APPEND_SYSTEM.md 的追加。替换默认提示可能同时移除原有安全提醒和工具使用说明，不能把“替换成功”当成“约束更完整”。项目里的 AGENTS.md 或兼容上下文文件适合写“原始观测只读”，但执行端仍应限制路径。

Skill 是带说明、参考与脚本的操作知识包，description 先进入可用目录，需要时再读全文；Prompt Template 则把一段重复输入展开为用户指令。给缺测修复建立模板可以统一任务要求，提供质检技能则可以解释步骤与脚本，两者不自动注册同一种工具。技能文本进入上下文后仍占容量，且不能把技能里的任意命令当成已获得权限。

压缩：循环外的事

上下文压缩改变的是下一次模型请求的历史投影，原会话记录仍保留。老消息变成摘要，近期消息原文留下，切点必须照顾工具调用与结果关系。若刚保留一条结果却丢掉发起它的调用，模型协议和可解释性都会受影响。

学习材料把压缩作为 AgentSession 的产品策略讨论。新版本也可能在工具批次之间准备下一次响应时触发阈值检查，因此“永远只在整个 run 外压缩”不宜作为跨版本结论。稳定的职责边界是：底层工具执行不应私自丢历史，会话层决定摘要、保留范围和持久化方式。

阈值应结合模型上下文容量、预留输出和可用 token 记录。约 2 万近期 token 是某些配置的默认值，不是适合所有模型的常量；取消或用量缺失的响应也不能直接当成准确估计。上下文溢出后的恢复与提前阈值压缩还可能有不同重试语义。

浮标修复任务的教学摘要
Goal: 空温度保留为 null，不再误记为零。
Constraints: 原始 CSV 只读；不得连接正式岸站。
Progress: 已定位解析分支，缺测测试尚未通过。
Decision: 区分空字段与合法的 0.0。
Next: 补断言，运行离线测试，核对变更文件。
Critical: 保留实际路径、测试名与原始错误信息。

这是新写的摘要内容示例，不是 Pi 固定输出。摘要应保留不可违反的约束、未完成状态和精确标识。反复压缩可能放大早期误写，任务恢复后应重新核对磁盘与测试结果，不能仅信摘要里的“已完成”。

人工介入

人工介入有不同强度。排队补一句话让模型调整后续方案，工具执行前拦截则可以阻止某个具体动作。二者不能互换：原始观测目录禁止写入，应由工具层检查，而不能只期待值班员及时发送 steering。

学习笔记描述可选的工具前钩子和 permission-gate 扩展：在真正调用前询问，批准才执行，拒绝则回传被阻止的观察。Core 不应假定每种产品都有终端选择框，RPC 和 SDK 场景可能由外部程序完成批准。具体事件与返回结构随版本核对，不把笔记中的内部名称当作永久公共 API。

审批记录至少要对应当前工具、参数、目录和请求 ID。用户批准写一份草稿，不等于批准随后修改原始记录。等待时还需支持取消和超时；UI 不可用时应返回明确状态，不能自动默认为允许。扩展与工具共享进程权限的事实，也要求开发者审查所加载的代码。

能力长在边缘

添加能力可以调整工具集合、提供技能、安装扩展或安装资源包。工具 schema 让模型知道如何请求，扩展把实际处理函数接进运行时，技能说明如何完成任务。斜杠命令则可能在输入处理阶段就结束，不一定成为模型能调用的工具。

比如读取浮标质检表是一个受限只读工具，输出设备 ID、时间范围与统计；“比较两版标定”的技能说明先取版本、再查适用期、最后给差异。把一份技能放到目录里并不意味着它可以直接访问设备，也不意味着工具表会自动多一个名字。

学习快照中的默认工具和扩展示例代表当时取舍，当前发行版的 MCP、计划、审批或其他功能以对应版本文档为准。可迁移的做法是核对实际加载资源与工具清单。扩展可以执行本机代码，来源、依赖、更新和权限都属于信任边界，不能把包安装视为纯文本配置。

四种外壳

交互 TUI 接受连续编辑输入并展示事件；打印模式适合一条任务后输出结果；RPC 使用 stdin/stdout JSONL 接受外部命令并输出事件；SDK 把会话放进宿主程序。这些方式复用 Agent 与会话机制，但交互能力不完全相同。

夜间校验程序适合将任务 ID 与 RPC 响应关联，不能把 stdout 里每一行都当作最终答案，日志也不应混入协议通道。SDK 的宿主需自行处理订阅、取消和资源释放。打印模式输出一段文本并不能证明测试全过，自动化仍应读取明确的检查产物与退出状态。

输入展开、技能触发、模型准备和上下文管理位于产品侧。若一个命令在 TUI 可用、RPC 下行为不同，应检查它依赖的 UI 能力和协议支持，不必先怀疑 Core 推理失效。无人值守任务应为需要人确认的情况设计可恢复退出，而不是无限等待不存在的终端用户。

延伸对照：Pi 的设计原则从哪来

会话树、事件和压缩可以借用成熟工程概念理解，但类比应止于机制相近处，不要因此推断恢复与隔离已经相同。

会话树与版本控制

对话树保留方案讨论的分叉点，版本控制保留文件版本，两者需要通过实际路径和提交状态关联。若解析器在旧分支上已经改过，当前会话重新讨论 null 并不自动产生新文件。工作区隔离、差异审查和测试才是代码探索的补充边界。

事件总线与可观测

事件驱动架构将控制监听与显示消费分开，和 waku observer、Hermes span 有共同目的。OpenTelemetry GenAI 可提供观测字段参考，但原始会话事件不等于已符合某个遥测规范。记录事件时要明确顺序、父子关系和敏感数据策略。

上下文压缩

摘要与外部证据应互补。被压缩的工具输出若仍可能用于诊断，应保留文件位置或可重查入口；摘要里的路径不能被改写成看似相近的新路径。为了省容量而丢掉“原始 CSV 只读”会直接改变后续允许行为，压缩质量需要用约束保持测试判断。

一句话总结

先找到状态持有者，再找它发出的事件和上下文投影，通常就能解释 Pi 中的大部分行为。Building Effective Agents 可作为简化工作流的对照，MCP 只解决其中的能力连接问题，不替代会话与执行策略。

动手验证

练习在无正式数据和无外部副作用的目录中进行。需要模型时自行配置，本文未启动这些运行。

练习一：制造一次分叉

围绕“空值转零”和“保留 null”各做一条讨论，用 /tree 回到共同前提创建新枝。记下当前 leaf，再观察旧枝是否保留。比较前先查看真实文件，确认切树并未自动撤销之前的改动。

练习二：读写一次 JSONL

在练习会话副本中逐行解析 JSONL，只输出条目类型、ID 与 parentId，不导出正文。画出当前根到叶的路径，找到压缩条目的保留边界，说明哪些记录存在于文件却未进入下一次请求。不要直接改正在写入的会话文件。

练习三：观察两种队列

让一个只读慢工具暂停几秒，先加入“后续不要写原始数据”的 steering，再排“结束后列出检查项”的 follow-up。记录它们进入模型请求的实际时机。取消后核对工具进程是否仍存活，不把屏幕停止滚动当作完全停止。

练习四：装一个扩展

选择官方示例中的一个无害扩展，先阅读它注册了什么以及是否依赖交互 UI，再在隔离目录加载。列出新增工具与命令的区别，验证禁用扩展后它们是否从实际能力清单消失。不要为完成练习加载不可信扩展或绕过已有权限。

回顾与自测

解析器修复任务有四份不同状态：活跃模型消息、会话树、磁盘代码和运行中的工具。Pi 的分层使它们各有管理入口，但没有把它们自动合成可回滚事务。

为什么中途输入要排队而非启动第二个 run？

两个 run 会竞争同一消息与工具状态。队列在规定边界插入输入，保留确定的推进次序。

压缩和删除历史有何区别？

压缩替换后续请求的旧上下文，原始记录仍可保留。删除是存储层操作，涉及隐私和恢复语义，不能混称。

回到旧节点能撤回已经发出的报告吗？

不能。会话树只改变所走路径，外部副作用需要业务补偿或撤回接口，文件也需另行恢复。

LangGraph 应用章节 会进一步对照图状态与会话状态的恢复差别。
