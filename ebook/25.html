用同一个问题检查自己有没有读懂

值班员希望助手检查 B17 浮标昨夜的缺测与异常，读取有效质检规程，整理报告，并在负责人确认后发送到指定值班组。数据读取、证据判断、确定性统计、审批和投递各有自己的成功条件。一个自然流畅的报告不能替代这些步骤的实际结果。1

本章给出重新构造的数字与材料，供纸笔演算。你可以暂停在每个中间状态，写出系统已经知道什么、还缺什么，以及哪一种失败应该停止。它不假设模型会照着理想路线执行，也不声称运行过观测设备、聊天平台或训练集群。

前半本的自行车任务与后半本的观测任务具有相同边界：建议不等于操作，相关不等于可信，保存不等于当前可读。下面用新的算例复查这些关系，而不依靠记住框架名来证明理解。

全项目共用的知识地图

同一任务可以沿执行链和支撑条件两条方向检查。链路中某一步有产物，并不代表下一步已经消费了它。

任务执行

两条支撑线

01–03：行动、规划、反思和搜索

先把这次巡检看成有限动作的组合。每种决策方式增加的状态不同，也会产生不同的验证需求。

Function Calling：先产生请求，再产生结果

模型请求 read_observations，参数为设备 B17 和约定时间窗；宿主校验身份、字段与范围后读取数据，再将结果绑定到原调用 ID。直到结果回流，模型才拿到真实记录。Schema 可以说明设备与起止时间的类型，不能证明操作者有权查询 B17，更不会自行读文件。

如果模型输出“报告已发送”，而本轮没有投递回执，应当记录为没有发送证据。调用请求、工具执行和外部确认是连续但独立的状态。

ReAct：每一步都让观察改变下一步

第一步读取数据，观察发现温度列使用摄氏度；第二步查询对应设备规程，观察发现校准期内外采用不同阈值；第三步按日期补查校准状态，才形成结论。若读取返回“时间窗无记录”，应停止统计并核实范围，而非继续生成一个看似合理的异常率。

这里的反馈来自工具实际结果。模型对下一步的简短说明可以辅助阅读，但不能当成其内部推理的完整记录，更不能替代证据。

Plan-and-Execute：知道下一步依赖谁

计划可先列“读数据、查规程、算指标、拟报告、送审批”。查询发现该设备刚更换探头后，应插入新探头的单位和有效规程核对。计划是会变的任务状态，已列在清单上不代表已经执行。

执行器需记录步骤依赖与已完成产物。重试规程读取时，无需默认重跑已成功的数据下载；但如果输入版本已变，就要使受影响的后续步骤失效。

Reflexion：把失败转成下一次策略

第一次报告把缺测计为异常，评价者根据标注样本指出分母错误。反思候选应具体写成“缺测与有观测但越界分别统计，报告各自分母”，下一次重新运行同一测试，检查统计行为是否改变。

一句“以后更仔细”不可验收。若评价器没有可靠标签，错误反馈还可能强化错误做法。候选经验需要来源、范围和回归题，而不是自动升级成永久规则。

LATS：保留不止一条候选路线

搜索可以保留“先检查传感器状态”与“先核对规程版本”等路径，为每个节点保存已见证据、成本、访问次数和评分。选择规则在已有高分与尚少探索的路径间取舍，预算达到上限时明确结束。

更多分支只扩大尝试空间，不会让错误评分变正确。若两条路径都引用同一份错误规程，它们不是两份独立确认，不能凭多数意见提高事实置信度。

04–06、20：检索与评测的算术

浮标资料可能来自维护手册、设备登记和质量规则。检索的目标是交付支持当前判断的证据，不是返回最多包含“异常”的段落。

分块：为什么 overlap 有用又有代价

设一份教学文本含 1350 个字符，窗口为 500、重叠 75，步长为 425。按固定窗口得到 [0,500)、[425,925)、[850,1350) 三块。边界附近的说明可能在下一块完整出现，同时有 150 个字符被重复处理。

这只是字符窗口示例。表格标题与阈值行若被分开，重叠也未必修复关系；真实分块应保留标题、页码、文档版本和适用设备，避免拼回没有依据的条件。

Embedding：相近不等于事实相同

“缺测要计入异常”和“缺测不要计入异常”可能具有相近的字词和向量位置，但业务含义相反。Embedding 用于发现候选，否定、有效期和适用范围仍需核对。设备编码与文档版本号则应保留精确匹配路线。

若向量召回只找到相似旧手册，而编号查询能找到新规程，先查看两路候选身份及其合并方式。只在旧候选上加关键词分数，无法把池外新规程补进来。

RRF：不用强行对齐两路分数

取教学常量 k=20。条款 A 在向量榜第 1、全文榜第 5，RRF 为 1/21+1/25，约 0.08762；条款 B 在两榜均第 2，得 2/22，约 0.09091，因此 B 在这组条件下略高。

名次融合没有把原始余弦和 BM25 分值当成同尺度数值。未出现在某榜的候选不应凭空领取那一路分数；具体常量与候选池改变后，应重新计算并评测最终效果。

MMR 与重排不是同一动作

若前几条候选反复引用同一段温度阈值，MMR 可在相关性与候选间重复程度之间取舍，为单位、校准条件等不同证据留位置。它不能保证留下的材料一定完整，参数失衡还可能选择多样但不相关的片段。

重排模型则联合阅读问题和各候选，细化相关判断。两者可以组合，但都只能处理传给它们的集合。缺失的设备例外条款需要回到召回或资料准备阶段补齐。

用数字分开看检索和生成

已知本题应有 5 个相关片段，返回 6 条，其中 4 条相关，则普通 Precision@6 为 4/6，约 0.667，Recall@6 为 4/5，即 0.8。第一条相关片段位于第 3 名，该题 reciprocal rank 为 1/3。

如果回答有 7 项可核实断言，仅 6 项有证据支持，可用 6/7 约 0.857 作为简化支持比例。这里的手算不等同于所有 RAGAS 版本的具体指标实现，也没有证明这 6 项覆盖了问题全部需求。检索覆盖、引用忠实和业务结论要分别验收。

Graph / Self / Corrective / Adaptive RAG 分别改变哪里

GraphRAG 主要改变材料间的关联组织；Self-RAG 将检索与证据支持等判断纳入生成控制；Corrective RAG 在证据不足时触发修正或补取；Adaptive RAG 按问题需要选择复杂度；Agentic RAG 则让工具循环参与查询路线选择。

这些名称不是可互换的优化开关。普通提示词自检不等于完整复现论文训练方法，多步查询也不必然比一次精确查表更好。用同一题集、候选范围和预算比较，保留不检索或简单检索的对照。

PDF 解析：不要让排版错误变成知识错误

扫描版维护手册没有可直接提取的文字层，双栏页可能被错误串行，阈值表又依赖行列关系。若把“适用探头”标题丢掉，数值仍然可读，却可能用于错误设备。应先辨别页面类型并抽样检查解析结果，再进入分块和索引。

保留页面、表格坐标或结构及原文件版本，便于从引用回查。OCR 分数或导出文件存在只能说明处理过，不能证明单位和否定条件被正确还原。

07：记忆到底怎么选

最近几轮消息适合解释“刚才那批数据”，摘要适合缩短过程，长期记录适合跨会话复用稳定要求。把三者混用，会让一次临时安排变成永久约定，或让必须保留的硬约束在摘要中消失。

以归一化教学信号计算：A 的相关、近期、重要分别为 0.85、0.30、0.90，B 为 0.65、0.80、0.40。权重 0.40、0.25、0.35 时，A=0.73，B=0.60。这个排序不能使已撤销的 A 重新有效，权限、版本和冲突应先处理。

例如“缺测单列”可以作为持续统计口径，而“本次先不要发送”应绑定当前报告。写入保留原话与来源，读取时保留日期与主体，修改后检查旧派生和缓存是否仍被使用。长期记忆通常改变当前输入，不等于微调模型权重。

08–11：协作、成本与持续运行

资料检索与数值统计可以独立并行，报告发送则依赖完整草稿和审批。先按依赖选择流水线、并行或状态图，再决定是否需要动态委派。每个子任务都有明确输入、结果状态和剩余预算，不能只发一段角色描述后等待自由讨论。

路由的两条轴

简单字段抽取可以优先使用通过相应测试的小模型，复杂冲突交给更强能力；服务不可用时则按可用性策略回退。两条路线分别回答“能否做对”和“能否获得服务”。一个不支持必需工具协议的便宜模型，不能直接作为兼容后备。

降级可以只提供带引用的材料清单，把尚未生成的分析标为未完成。不要为了保持响应非空，悄悄移除审批、证据或隐私限制。

熔断的状态变化

正常 CLOSED 接收调用，满足失败条件后 OPEN 快速失败；经过等待，HALF_OPEN 只放少量探测，通过才恢复。应区分认证错误、速率限制和网络故障，不把所有错误都累成同一恢复动作。

单请求重试受剩余截止时间限制，熔断保护的是一批后续请求。客户端、网关和后端的重试次数若相乘，可能使故障服务承受更多压力，因此需要统一预算和 attempt 记录。

费用与缓存的纸上账本

假设虚构价格为每百万输入 3 元、输出 12 元。本次输入 1600、输出 250，则为 0.0048+0.003=0.0078 元。失败后再调用一次，仍应根据两次实际 usage 记账，不能只计最后成功答案。真实计费还取决于模型、缓存、批处理和供应商规则。

同一个“昨夜异常多少”的问句会因设备、时间窗和口径版本得到不同结果。缓存键至少覆盖这些条件及权限范围。语义接近不能覆盖身份边界，命中后仍需确认结果适用。

Loop 的完成条件

每天触发巡检只是定时开始。完整 Loop 还需要确定数据窗口、检查规程版本、运行统计、处理不确定项、请求审批，并根据结果结束或继续。触发、执行和反馈不是一件事。

若昨日数据未齐，下一轮可保留待核查状态，而不是不断生成看似完成的日报。持续运行需要可恢复进度、停止条件和成本上限，重复调用本身不构成学习。

12：测试、CI 和运维脚本

确定性单元测试检查分母与筛选，集成测试检查资料或服务接线，端到端测试检查从任务输入到投递回执。固定模型替身适合检验消息装配，真实模型题集适合观察概率输出，二者不能互相冒充。

持续集成负责自动获得检查证据，持续交付保持可发布状态，自动部署才会把版本真正送入运行环境。GitLab 的 stage、needs、rules 与 Runner 条件会改变哪些任务执行；cache 保存可重建加速内容，artifacts 保存后续要消费的产物。Jenkins 同样需区分调度控制与实际执行环境。

09-writing 补课：日志巡检不是一堆命令名

  1. Python 可用字典按任务 ID 聚合事件，用集合去重来源，用列表保留顺序。async 函数直接调用阻塞读取仍会阻塞事件循环；应在合适边界处理 I/O，而不是只改函数声明。

  2. Shell 对路径和变量加正确引用，明确失败退出与管道语义。目录名含空格、前一段命令失败而最后一段成功，都应成为脚本测试输入。

  3. 巡检程序逐行解析事件，核对设备与时间，按任务聚合开始、结果和结束，再输出成功、失败、取消及未知。命令行阈值只决定何时告警，不应悄悄改写统计数据。

  4. 进程未响应时，先看运行状态与监听，再查网络、权限和依赖日志。已有 core dump 时保留版本与回溯材料，避免重启覆盖首错；教材不以盲目重启作为根因判断。

纸上记录有任务 J8 的 start 和统计结果，却没有投递回执及 end。可判定统计曾产生结果，不能判定消息送达；最终完成状态仍未知。将未知单列，可以避免因日志缺失得到虚高成功率。

13：从 token 到训练的十个台阶

Agent 的运行系统消费模型输出，训练则改变模型参数。下面把两条路线分开，使用新的小数字理解模型课程的各阶段。

part_1 · 模型不是在背字符串

分词把观测说明变成离散 ID，嵌入给每个 ID 一个向量，位置机制保留顺序。注意力以 Q/K 计算匹配，归一化后加权 V；因果掩码限制位置读取未来。前馈层、残差与归一化共同组织信号传播，不能用“模型在注意什么”替代数值关系。

假设某位置对两个可见位置的缩放分数为 ln(2) 与 ln(3)，softmax 权重为 2/5、3/5。若标量 V 为 1 与 6，加权结果为 4。真实实现对向量和批量矩阵处理，这个算例只验证归一化与加权。

part_2 · 训练为何错开一位

用 ID 序列 [7,12,4,9]，输入 [7,12,4]、目标 [12,4,9]，每个位置学习预测下一个 ID。交叉熵与反向传播把预测误差转为梯度，优化器据此更新参数。

训练误差降低而验证误差升高，需要检查泛化与数据泄漏。温度和采样截断改变生成选择，不能视为重新训练，也不会补回缺失资料。

part_3 · 现代结构与 KV Cache

RMSNorm、RoPE 和 SwiGLU 分别涉及尺度、位置与门控前馈组织。KV cache 保存已知位置的键和值，在后续生成中复用，不需要重新计算整段前缀的相同 K/V。

缓存不是最终答案，也没有消除新位置读取历史的成本。长上下文与并发会增加状态，部署时应同时记录权重与请求缓存，而非只看模型文件大小。

part_4 · 把训练做稳

BPE 等分词方法组织词表与序列长度；混合精度要兼顾数值与硬件；梯度累积把多个 micro-step 的贡献合到一次更新。学习率计划、随机状态、数据位置与优化器都影响继续训练。

例如每数据副本一次 2 份样本，3 个副本、累积 4 次，global batch 为 24。若每次都清梯度并更新，就不再是同一次 24 样本更新。恢复时只加载权重也无法保证后续等价。

part_5 · MoE 是模型内部路由

MoE router 为 token 选择部分专家，不是为整项业务选择不同厂商模型。专家分布与实际路由会影响负载，少数专家过热可能让其他设备等待。

总参数容量增加不意味着每次激活全部参数，也不意味着通信免费。模型内路由、服务层模型路由和多 Agent 分工应分别核对，不能只因都叫路由就合并比较。

part_6 · SFT 教格式与行为

SFT 用指令与期望响应构造监督目标，按数据约定选择参与损失的位置。若把不应预测的 padding 或提示部分误计入，loss 仍可下降，却未必学到预期行为。

它可以学习输出格式和任务模式，但不是资料库的即时更新方式。新增一份浮标手册可通过检索进入输入，是否还需微调，要由明确失败和训练收益决定。

part_7 · 奖励模型学相对偏好

对同一个问题给出更偏好与较差响应，成对训练鼓励奖励分数拉开。若两者分数差为零，典型 logistic 成对损失为 ln(2)；提高偏好响应的相对分数会降低该项损失。

偏好标签反映标注目标，不能自动成为事实真值。若训练标签偏爱自信措辞，奖励可能鼓励没有证据的结论，需要独立事实与安全检查。

part_8 · PPO 限制一次更新走多远

PPO 使用策略采样、奖励和优势估计，对新旧概率比的更新施加裁剪等限制；还可用参考策略的 KL 约束控制漂移。它不是简单把最高分答案复制回训练集。

约束与奖励都只是代理。如果模型学会迎合评分器而忽略证据，训练奖励可能上升而巡检质量下降。保持独立测试集和失败类型统计，才能发现这种偏离。

part_9 · GRPO 用同题一组回答作参照

同题产生一组回答，使用组内相对奖励提供训练信号。教学奖励 [0,2,4] 的均值为 2，未标准化的相对差为 [-2,0,2]。具体实现是否除以标准差、怎样加 KL 和裁剪，应查看对应代码。

若全组奖励相等，就缺少区分方向；若奖励规则错误，相对比较也不会自动修正。这个小算例没有证明某次 GRPO 训练已经收敛。

tiny model training 与 total_time

tiny model training 用小规模语料、分词、模型、训练与采样组成闭环，便于观察每个产物。total_time 等 Notebook 记录辅助过程，不是另一种架构或性能保证。

比较耗时时确认是否包含预热、数据处理和保存，并固定有效 token 数。能生成一小段文字只证明某些环节连通，不证明具备可靠规划、权限判断或工具使用能力。

14–18：在真实运行时里找到同一套概念

把上述概念带回运行时，应先确定当前讨论的是源项目快照还是本机安装版本，避免把教学笔记当成全部发行行为。

Hermes、waku、Pi 的对照

Hermes 材料展开多会话、平台入口、执行环境与记忆接线；waku 用较小工程集中展示约束、循环、记忆和评测；Pi 笔记区分核心运行与交互外壳。相近职责可能在不同层实现，不能仅按同名模块推断可直接替换。

会话树切回旧节点只改变接下来的消息路径。已经写出的文件、发出的通知和真实操作仍存在。压缩减少活跃上下文，不等于删除原始历史；持久化会话也不一定提供任意步骤恢复。

LangGraph 三组应用

课程、Chatbot 与 TripMate 分别展示图构建、交互会话和角色协作等接法。新的观测申请可以映射为取数、核规、统计、审批和发布节点，但这只是迁移演算，不表示原应用已经提供浮标功能。

checkpoint 记录图状态，外部投递仍需幂等。审批节点恢复可能重放前置代码，应把不可重复动作放到清晰边界，并用拒绝分支确认未发生投递。

DeepSeek Harness 与 Edge Agent

DeepSeek Harness 与 Edge Agent 在本仓主要作为架构研究材料阅读。前者讨论模型、工具、配置和会话的可替换边界；后者讨论本机资源、权限与出域。文档里出现设计并不表示已经交付完整实现。

教学 3B 模型按 4 位保存，纯权重下界约 1.5 GB，实际还需元数据、KV、激活和运行时。模型可本机运行，也不代表调用的搜索、遥测或云后备不出域；应沿每条数据传输实际核对。

大纲与个人笔记：如何成为可验证的学习路线

主题大纲安排学习范围，个人研究材料提出观点、方法与假设。把它们转成工程练习时，最好交付可复查的输入、预期状态、运行证据和未测范围，而不是只完成阅读页数。

例如主张“摘要能保留关键约束”，可构造一段明确禁止发送报告的对话，在摘要前后运行同一检查，确认禁止条件和适用报告仍在。然后补一个允许发送的反例，防止系统靠全部拒绝取得表面安全。

同样的方法可检验记忆、协作和模型路由：先指出失败，再限制改动，再比较结果与成本。模糊主张拆成这些问题后，才知道需要代码测试、模型评测还是人工审核。2

读全书必备的小词典

Token / Context window
输入输出的离散计量与单次处理容量。字数估算不能替代目标 tokenizer 的实际长度。
Schema / Tool call
数据结构合同与一次动作请求。前者不授予权限，后者不证明执行成功。
Embedding / Chunk / Rerank
用于匹配的数字表示、可追来源的资料片段、对已有候选做更细选择。排序无法凭空取回池外证据。
Session / Turn / Iteration
跨消息的会话、一次用户输入的处理，以及其中一次模型和工具交互。三个 ID 和生命周期不必相同。
State / Checkpoint / Transcript
当前运行数据、可用于某种恢复的状态快照、历史事件记录。记录齐全不自动意味着外部动作可撤销。
Harness / Hook / Skill / MCP
围绕执行的约束系统、生命周期接入点、按需操作知识、外部能力连接协议。能力连接与业务授权需要分开。
Idempotency / HITL / Gate
重复调用受控地产生同一业务结果、人工参与决策、不满足条件时阻止继续。审批应绑定对象版本与有效期。
Trace / Eval / Regression
一次运行的关联轨迹、按约定标准判断过程或结果、变更导致的相对退化。可观测并不等于自动判对。
Mock / Fixture / Snapshot
替代依赖、固定样例、时点状态。它们使实验可重复，但其有效性不能外推到未测真实服务。

阅读毕业题

需求现在升级为“每日自动统计 B17 并向值班组发送”。先确认设备归属、时区和数据窗口，明确异常与缺测的定义，指定规程版本、审批人、接收组及投递失败策略。还要问重复触发怎样去重、数据不齐怎么办、谁能取消和修改计划。

参考设计：按证据与权限组织，不预选框架

定时器生成带批次键的任务；服务确定身份与可读设备；读取观测和有效规程，保留来源版本；确定性程序计算有效、缺测与异常集合；模型根据这些结果拟报告并标注不确定项；审批绑定报告版本；授权后用稳定业务键投递并查询回执；保存各阶段状态、成本和失败原因。

把无数据、错误单位、旧规程、审批拒绝、发送超时但实际成功、重复 tick 和跨组查询分别加入测试。生成成功但发送失败应保留可重投结果，不能从头重复全部动作。新版本仅在回归与权限检查通过后发布，并保留撤回配置。

这份设计允许先用简单任务表和显式代码完成。只有实际失败证明需要动态规划、多角色或新记忆机制时，才增加相应组件；基础授权、审计与幂等不随复杂度降低而省略。
