为什么要自己写一遍

一批浮标每十分钟上报温度、电压和质检标记。助手能解释“温度跳变为什么暂不发布”，却偶尔把缺测说成正常。排查时需要区分三种原因：观测记录没有进入上下文，生成分布偏向常见句式，或者后训练奖励过分偏爱肯定回答。三种原因分别需要检索修复、模型分析和训练数据调整，不能都归为提示词写得不够好。

07-llm_from_scrach/ 的课程把分词、前向传播、训练和对齐拆成小实现。这里用它建立计算直觉，不尝试从几条海洋记录训练出专业预报模型。教学日志可以是 B17 temp=18.4 flag=suspect，模型学习的是这些符号的条件分布；它并未通过这段文字接触真实传感器，更没有自动获得计量学知识。

阅读时可以沿两条证据线做记录：张量形状是否对得上，更新前后的目标是否一致。前者帮助发现转置、掩码和缓存错误，后者帮助发现模型优化了流畅度却损害质检可靠性的情况。能够逐项说明输入、参数和输出，比记住架构缩写更有用。

核心 Transformer

设三条日志已经编码成三个向量，每个向量维数为 4。单头注意力先用可训练矩阵把它们投影为查询 Q、键 K、值 V。查询与键的点积形成位置间的匹配分数，softmax 再把分数转成权重。值向量承载被汇总的信息，查询与键只负责决定怎样汇总。

X.shape = (1, 3, 4)
Q = X @ Wq; K = X @ Wk; V = X @ Wv
S = (Q @ K.transpose(-1, -2)) / sqrt(4)
S[i, j] = -inf  if j > i
Y = softmax(S, axis=-1) @ V

这是形状说明片段，不是完整可运行模型。最后一个位置对三个可见位置的分数若为 [0, ln(2), ln(5)]，权重就是 [1/8, 2/8, 5/8]。取值向量的某一维为 [8, 4, 0]，该维输出为 1 + 1 + 0 = 2。这个数由前缀共同决定，不是从某一条日志原样复制。

因果掩码限制的是每个位置能够读取的信息。第二个位置只能看前两个 token，移去掩码后它能看到第三个 token，训练便可能偷看目标。最后一个位置没有未来位置，因此用它观察掩码差异通常看不出问题。缩放因子则在常见独立分量假设下控制点积方差，避免维数增加时 softmax 过于尖锐；它不保证所有真实激活都具有相同方差。

多头会在不同投影上重复这种汇总，拼接后再投影回模型宽度。前馈网络对各位置做非线性变换，残差提供旁路，归一化调整尺度。不能仅凭某个头的可视化就断定它专门负责电压或温度，模型内部表示通常没有这样的人工标签。

训练一个微型语言模型

把一条教学日志编码为 [11, 42, 7, 93, 5]。一个长度为 4 的训练窗口以 [11,42,7,93] 为输入，以 [42,7,93,5] 为目标。目标相对输入向后错开一个位置，输入并没有被倒序。若真实下一项的预测概率是 0.25，该位置交叉熵为 −ln(0.25)≈1.386；概率升到 0.5，损失降为约 0.693。

训练循环需要清空梯度、前向计算、汇总有效位置损失、反向传播和优化器更新。忘记清空梯度会改变有效批量，padding 未掩码会让模型把大量填充位置当成目标。字节词表有 256 个基本值，中文通常占多个 UTF-8 字节，所以字节级模型不能笼统称为一字一个 token 的字符模型。

检查项浮标日志里的反例如何识别
数据划分同一天的相邻窗口同时进入训练和验证按时间段或设备分组留出，防止近重复泄漏
损失下降记住 B17 固定格式，却无法处理新设备分开查看训练集与留出设备损失
采样高温度生成不存在的质检标签解析生成字段，检查是否属于允许集合

温度、top-k 和 top-p 在推理时改变抽样分布，不会补回训练中缺失的观测。即使模型能生成格式正确的 flag=good，是否应发布仍需依据真实数据与规则决定。

现代架构改造

现代解码器常调整归一化、位置表示和前馈层。RMSNorm 不减去均值，而按均方根缩放；RoPE 对 Q、K 的成对分量做位置相关旋转，使点积体现相对位移；SwiGLU 用门控分支控制前馈特征。它们的效果依赖参数配置和训练条件，不能脱离实验把每一种替换都称为无条件提升。

推理优化可以用一条追加日志理解。已有 100 个 token，生成第 101 个时，KV cache 保存前 100 个位置的键和值，只对新位置计算新键值。新查询仍要与历史键做匹配，缓存并未消除对历史的注意力读取。训练通常并行处理完整窗口，推理则要等待上一个生成结果才能决定下一个输入。

机制变化边界检查
GQA多个查询头共享较少的键值头检查头数可整除，缓存形状按键值头数计算
滑窗新 token 只读最近一段历史早期设备限制可能离开窗口，需要显式重注入
attention sink保留开头少量位置以改善某些流式设置它不等价于完整保存全篇语义

课程的 part_3/attn_modern.py 集中展示这些组合。比较缓存开关时固定权重、前缀、精度与位置索引，先比 logits 再比速度。若位置偏移错了一位，程序仍可能生成通顺文本，但其计算已经不再等价。显存不足时也应分清权重、KV 缓存和临时激活的占用。

规模扩展

假设一张卡每次只能装下 2 条日志窗口，目标有效批量是 16。可以累积 8 个微批次后再更新一次参数；若每个微批次的损失已经取平均，累积时还需按 8 缩放，才能与目标梯度尺度一致。学习率调度和步数应以优化器更新次数计数，而不是每看到一个微批次就前进。

BPE 把常见符号组合合并为子词，可能缩短序列，但浮标编号和异常码仍可能被切成多个 token。混合精度减少部分张量的存储与计算开销，也会引入溢出和舍入误差；具体使用 BF16 还是 FP16 要看设备支持及数值范围。warmup 让早期更新逐渐增大，不负责修复错误标签。

检查点至少要说明保存了哪些状态：只有模型权重适合加载推理，等价续训还涉及优化器、调度器、随机状态、数据迭代位置和混合精度相关状态。恢复后可以先对比下一批的样本编号与学习率，再检查损失是否连续。TensorBoard 或 wandb 用于观察记录，不能代替这项恢复验证；外部记录服务还应避免上传原始敏感观测。

混合专家

MoE 把部分前馈层换为多个专家和一个路由器。以教学设定的 4 个专家、每 token 选 2 个为例，8 个 token 会产生 16 次专家分派。均衡时各专家约收 4 次；若分派数变成 [12,2,1,1]，单个专家会拥堵，其他参数很少参与学习。负载均衡损失、容量约束及路由策略用于处理这种偏斜，实际实现各有差异。

路由器学习的是内部表示与任务损失的关系，不能预先断定某专家就对应海温、某专家就对应波高。模型的总参数可以大于每次激活的参数，但训练或部署仍需存放全部专家，跨设备时还会增加通信。课程的 gating.py、experts.py 和 moe.py 可分别追踪选择、计算与合并；检查时要看门控权重如何归一化、未选专家是否确实未参与该 token 的前向。

从 SFT 到 RLHF

预训练可能把“请解释缺测”接成另一条日志，SFT 才用任务示范塑造回答行为。教学回答规定先报数据来源，再区分已证实与待检查原因，并禁止把缺测填成实测值。训练信号来自标注样本，不会自动核验海洋事实。[1]

SFT 监督微调

格式错误、标签分隔符不一致或 padding 未屏蔽，都会让梯度流向意外位置。监督全部文本也是一种可选目标，不能说只要训练提示位置就必然复述问题。

奖励建模

同一问题给两个候选：A 明说缺测，B 编一个温度。偏好标注选择 A，奖励模型学习让 r(A)>r(B)。Bradley–Terry 形式的成对损失可写作 −log σ(r(A)−r(B))。它约束分数差，不要求每个分数是已经校准的正确率；把 0.9 当成九成可信会误用这个模型。

RL 优化

强化学习从当前策略采样回答，再按奖励更新生成概率。若奖励只检查“是否输出完整字段”，模型可能补造缺失字段以拿高分。因此应同时有不补造观测、引用有效、格式可解析等检查，并留一组独立质检题。KL 约束限制偏离参考策略，但参考策略本身的错误不会因此消失。

PPO 与 GRPO

PPO 使用旧策略采样的轨迹，计算新旧策略概率比，并裁剪过大的更新激励。语言模型的 RLHF 常结合价值估计、参考策略 KL 和最终回答奖励。价值头预测未来回报以构造优势，不负责独立判断浮标记录真假。裁剪阈值也不是对每个参数变化的硬限制。

GRPO 取消独立价值估计，利用同一题的一组回答构造相对优势。设四个候选奖励为 [0,2,2,4]，组均值为 2，中心化奖励为 [−2,0,0,2]。常见标准化形式还会除以组内标准差与小常数之和，具体课程实现应查 grpo_loss.py。全组同分时几乎没有组内区分信号，重复采样也不一定提供有效梯度。

教学计算，不调用训练框架
rewards = [0.0, 2.0, 2.0, 4.0]
mean = sum(rewards) / len(rewards)
centered = [r - mean for r in rewards]
assert centered == [-2.0, 0.0, 0.0, 2.0]
# 这只计算中心化信号，不代表完整 GRPO 损失。
print(centered)

DeepSeekMath 提出的 GRPO 可减少价值模型相关开销，代价仍包括每题多样本生成、参考策略计算及奖励获取。若奖励偏爱长答案，策略可能学会把同一个质检结论写得很长。检查奖励与篇幅的相关性、在独立题集核对事实，比只看平均奖励上升更有说服力。[2]

Agent 在一次任务中根据批评重查数据，改变的是当前上下文；这里的优化改变模型参数，影响后续所有相关输入。两条改进路径需要不同回滚方式，前者可重开任务，后者通常要保留旧权重和训练配置。

架构

Attention Is All You Need 给出 Transformer 的注意力与层结构；阅读解码器时需留意因果掩码。RMSNorm（arXiv:1910.07467）、RoFormer 和 GLU Variants（arXiv:2002.05202）分别改变尺度处理、位置关系与前馈激活。GQA 的共享键值头属于存储与建模折中，FlashAttention 则通过访存组织减少注意力实现的代价，并没有把普通精确注意力的运算关系变成滑窗。

Mixtral of Experts（arXiv:2401.04088）可用于对照专家数量与激活参数的报告方式。读数字时分别记录总参数、单 token 激活参数、硬件和吞吐口径，避免把不同口径拼成一个速度结论。

训练与对齐

Chinchilla（arXiv:2203.15556）讨论给定训练计算量时参数与数据的配比；LoRA（arXiv:2106.09685）限制可训练更新的形式。两者没有替你决定浮标数据的授权和标签质量。InstructGPT 展示偏好后训练链路，PPO（arXiv:1707.06347）提供策略优化基础，DeepSeekMath 可核对 GRPO 的优势与目标定义。

阅读目标优先核对
减少显存是减少可训练状态、键值缓存，还是减少激活专家
提高可信度奖励来源、独立测试集、事实错误分类
重现训练分词器、数据划分、超参数、检查点与随机性

对 Agent 工程师意味着什么

部署质检助手时可以据此作三项选择：记录太长先考虑证据筛选，稳定输出格式可尝试监督微调，明确且可验证的任务奖励才适合讨论强化学习。模型输出更肯定并不表示传感器数据更充分，任何训练路线都应保留缺测、拒答和人工复核的测试题。

动手验证

以下练习先给验收标准，再由读者决定手算或运行课程。没有要求访问真实浮标、训练大模型或上传日志。

练习一：手算一次注意力

用本章 [0,ln(2),ln(5)] 的分数重算权重，把第三个值从 0 改成 8，输出应从 2 变成 7。再查看 part_1/attn_numpy_demo.py 的第二个位置，比较掩码开关。记录哪些位置的可见集合变化，不能只看最后一个位置。

练习二：观察采样参数

固定一组 logits [0,1,2]，分别用温度 0.5 与 2 计算 softmax；较低温度下最大值占比应更高。在 part_2/sample.py 做同样对照时固定前缀与种子，记录非法质检标记的次数，不用一两条生成结果证明整体质量。

练习三：对比有/无 KV cache

为 part_3/demo_generate.py 准备相同输入，先验证缓存前后的下一步 logits，再计预热后的耗时。分别报告前缀处理与逐 token 解码，不把首次加载时间混入缓存收益。没有相应设备时，只计算缓存形状与字节数即可。

练习四：读懂 GRPO 的一步更新

查 part_9/GRPO_TRAINING_EXPLANATION.md 与损失实现，圈出均值、标准差、概率比和 KL 的位置。用 [3,3,3,3] 替换本章奖励，解释为何缺少相对偏好；再说明“整组都错”为什么也可能无法从相对奖励中被识别。

回顾与自测

对一条浮标日志，模型先把 token 转成表示，再按可见位置汇总信息；训练把预测误差转为参数更新；后训练另加示范或偏好信号。故障定位时应明确是哪一环的输入、计算或目标出了问题。

注意力权重之和为 1，是否意味着答案可信？

归一化只说明值向量按一定权重组合。输入缺失或内容错误时，权重仍可完全合法，输出却没有可靠观测依据。

缓存为什么不能把长历史的代价全部消掉？

它复用旧键值的计算，但新查询仍读取缓存。历史变长还会占用更多缓存空间，长序列读取也有开销。

奖励模型一定是 RLHF 的必备独立服务吗？

人类偏好常通过学习到的奖励模型扩大反馈规模，但有可验证答案的任务也能用规则奖励。选择取决于奖励是否可靠，不取决于流程图中是否画了打分框。
