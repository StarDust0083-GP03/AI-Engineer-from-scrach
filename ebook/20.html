把检索从固定步骤变成可选择的工具

“辛苦了”不需要检索，“B17 的温度精度和发布前质检要求是什么”则涉及两类资料。固定 RAG 若只查设备说明，会遗漏发布规则；每次都查全部库又会增加等待与无关上下文。Agentic RAG 把检索暴露为工具，让决策器依据当前问题与已有观察选择是否继续取证。

02-RAG/06 Agentic RAG 的两份脚本展示这种控制方式，工具背后的文本与搜索打分仍是教学模拟。本章重新构造浮标问题与证据，不沿用示例库中的业务案例。源码使用的 product、policy、tickets 是真实标识，新场景分别把它们类比为设备说明、发布规范和故障工单。1

离线 mock 是关键词和计数驱动的决策器，不是隐藏的智能模型；网页搜索也不代表访问了实时站点。比较模型决策与宿主执行时，先确认当前运行的是 mock 还是真实 Provider，否则会把预设路线误当模型稳定行为。

一条主线，三条出口

一次取证任务应同时维护证据与退出原因。取了几次资料并不自动等于完成验证。

每轮决策

不是所有结束都叫成功

三幕演示：不运行也能走完整条链路

下面的三幕均为纸上构造。输入、证据与计算是新教学数据，脚本原有 mock 不会自动包含这些浮标资料。

第一幕：你好

值班员输入“辛苦了”。预期路线是直接返回一句回应，不访问设备说明或工单。验收看工具计数为零，而不是看文字是否热情。若真实模型仍检索了资料，应记为路由噪声，不是声称“模型已经理解所有寒暄”。

第二幕：产品检索和退款政策分别说了什么

本幕让同一个问题需要两个库。新问题是“B17 温度字段的分辨率是多少，缺测时能否发布为正常值”。设备说明库的教学片段 D7 写“显示步进 0.01 °C，分辨率不等于测量准确度”；发布规则库的片段 Q4 写“缺测保留空值，不得作为正常实测发布”。

轮次请求与观察新增状态
1search_docs 选择 product，返回 D7知道字段显示步进，尚无发布依据
2search_docs 选择 policy，返回 Q4补齐缺测规则，与第二个调用编号配对
3不再请求工具，组织回答报告两个结论各自的证据，不能把 0.01 °C 写成精度保证

若第二轮没有把第一轮观察回填，决策器可能再次查设备库。若把结果放错调用 ID，协议与证据归属都会出问题。原离线版只按既定逻辑汇合文本，不具备自动断言核验，不能从“确实查了两个库”推断每一句回答都受支持。

第三幕：产品库超时

教学故障是设备说明库无法返回。原 demo 对指定库模拟等待后抛 TimeoutError，捕获后直接给固定限制提示并结束，不会再调用模型完成一份新分析。读者应把这个分支理解为提前退出，而非真实的备用模型服务。

在 B17 问题里，规则库即使可用也不能补造设备分辨率。合理输出可保留已知缺测政策，并明确设备参数未核实；若脚本实现直接终止，则应如实解释没有继续取证。不要给“数据库超时”填一个空列表后让下游当成“没有相关制度”，两者含义不同。

两份示例并不是同一个系统

两份示例共享主题，但决策器、检索与故障路线不同，必须分别追踪。

字符重叠并非语义检索。教学输入“B17 温度”与“B18 温度”有大量共同字符，编号不一致也可能被排前；正则将连续中文当词段时，两个语义近似句也可能零交集。这些实现可演示空结果和误召回，不能当作向量数据库的质量测试。

低分是否过滤也改变行为：强行取前 k 条可能把无关文本塞给模型，过滤零分则可能频繁空结果。应分别记录命中的 ID 与分数，不只看最后能否生成一段文字。换成真实向量库还需补嵌入、索引、权限和版本管理。

计算器到底帮了什么

假设 18 台浮标各返回 24 个时槽，计划检查总数为 18*24=432。计算器负责算术，模型负责说明这是时槽数而不是有效观测数；若其中 12 槽缺测，有效值才是 420。两种数量必须有明确定义，不能算完就都叫数据量。

示例对白名单表达式限制字符并禁用部分执行环境，这不等于完整沙箱。超长表达式、大指数或资源消耗仍要限制。安全设计宜采用受限语法和运算预算，不能让用户任意字符串直接进入通用执行器。

提示词约定与程序硬限制

硬限制必须能在程序中找到计数或判断。提示里写“最多补查两次”，若代码只限制外层模型循环 5 次，就不能宣称补查次数被单独强制。一个模型回复里请求多个工具，也会让总调用数超过外层迭代数。

参数 JSON 解析位置同样重要。坏 JSON 如果在工具异常捕获范围之外，程序可能直接中止，模型不会得到可修复观察。库名、设备 ID 与 top_k 还需要验证，不应把有效 JSON 当成有效业务参数。工具结果也应区分无命中、超时和未授权。

源码的可选 LangSmith 包装用于观察调用，未配置时不影响基本循环。启用后问题与证据可能出域，应先检查是否允许记录原始设备数据。计时列表与注释数量不一致、没有金标与重复运行等因素，也意味着输出耗时不是质量结论。2

完成验证应逐条连起问题、返回片段与答案断言。D7 只支持显示分辨率，不支持准确度或质保承诺；Q4 只处理缺测，不自动判断某次突变的物理原因。任何新增结论都需另有证据或明确标成推测。

两份工具结果都有来源，答案为何仍可能错？

可能混用型号、错解单位、使用过期规范，或在生成时增加了证据中不存在的结论。来源存在只是开始，还要检查适用性与断言关系。
