20 节课程不是 20 套 Agent

06-harnes/learn-claude-code 的 20 节分别放大一个机制，不能把后面的单节演示默认当成前面保护全部累积的完整产品。综合课程重新组合若干能力，也仍需区分接口示意、模拟通信和可靠并发实现。

本章使用新任务：“修复浮标时间字段解析，空时间不得当作当前时刻；增加跨日测试，并由两名执行者分别核对解析与报告展示。”所有数据为离线假报文，禁止访问正式岸站。这个任务需要计划、文件修改、测试与交接，适合检查机制之间的接缝。1

一次工作完成应有测试证据、任务状态和清理结果，而非仅返回“修好了”。课程结构可以帮助定位谁负责这些状态，但不会替学习者补齐所有安全与恢复保证。

机制应该挂在哪个位置

把一次决策所需的状态画成两个检查面，能够发现遗漏的保护究竟位于请求前还是执行前。

s01–s04：行动与权限

前四节为“模型提出请求”增加可执行能力与控制点。只读练习也应使用隔离工作目录。

s01 · 一个循环

模型看到空时间样本后请求读解析器，宿主执行读取，再回填输出，模型才决定修改。最小循环按返回结构或停止原因判定是否继续，具体版本不同。shell 工具继承进程权限，不能因为它出现在教学循环里就认为命令没有真实副作用。

自然返回文本只是循环结束，缺测、跨日和时区用例是否通过还需独立验证。应保存退出原因而非把所有结束统一叫 success。

s02 · 工具注册表

读、写、精确替换和查找各自有 schema 与处理函数。模型可见声明和宿主分发表必须同步，工具名存在但无实现时应明确报错。一个模型回复里的多个调用，教学版通常顺序处理，不宜自动改为并行写同一文件。

文件工具可以检查工作区路径，shell 却可能绕过它直接读写。路径校验只覆盖实际执行该校验的入口，还需考虑符号链接与真实路径，不能把所有工具都算作已被保护。

s03 · deny / ask / allow

硬拒绝优先，再处理需询问和直接允许的范围。新任务可允许读取练习目录、询问外发报告、拒绝改正式数据。未知路径与参数应走明确默认策略，不能因没有命中字符串而自动允许。

简单命令字符串规则无法完整理解 shell 展开、子进程或编码，也不等于操作系统隔离。教学 deny / ask / allow 展示决策流程，真实安全仍需权限、沙箱和受限工具配合。

s04 · Hook 是控制点，不是装饰

输入、工具前、工具后和停止前钩子适合挂不同控制。PreToolUse 可以拦截写入原始报文，PostToolUse 可以记录测试退出码，Stop 可以要求补缺失验收。只有被实现消费的返回值才有控制力，不能看到 hook 名称就假定它能改请求。

停止钩子若发现没有跨日测试，可要求继续一次；连续失败应计入预算并转人工。否则验证器反复要求“再检查”也会形成无限循环。

s05–s10：计划、上下文与记忆

计划与上下文都服务任务推进，但持久性、真实性和容量不同。将这些状态写清可以避免把提示提醒当成强制工作流。

s05 · Todo 是注意力提醒

Todo 可记录“定位解析、修改、补测试、核对展示”，状态为待做、进行中和完成。进程内 Todo 重启可能丢失，完成标记也只是模型或工具写下的声明。若模型说跨日测试完成却无运行记录，应保留未验收状态。

未更新清单的提醒能把任务重新带回注意范围，不会自动完成，也不能替代持久任务依赖。

s06 · 子 Agent 隔离的是对话，不是文件

让子 Agent 单独查时间字段流向，它使用新对话，返回路径与结论，主会话不必吞入全部中间日志。课程中对子 Agent 限制递归委派与迭代，有助于控制展开。

新对话隔开的是上下文，不是磁盘。子 Agent 若有写工具仍会改变同一工作区，应限制只读，或采用单独目录。摘要返回后也需验证精确路径和未确认推断。

s07 · 技能目录常驻，正文按需读取

启动时只列出“报文质检”技能简介，遇到跨日处理再加载正文，可以节省常驻提示。正文提供测试方法、边界与脚本入口，但不会自动授权运行所有脚本。

加载后的内容仍在历史里占容量，除非后续裁剪或摘要；技能不是读完就消失的免费知识。更新技能版本时也要能解释当前会话读的是旧版还是新版。

s08 · 四种压缩，按损失最小的顺序使用

大测试输出先写完整文件，模型只看有用预览；随后可以裁剪旧消息、替换不再需要的旧工具正文，仍过大才做摘要。先保存再缩减，才能给未来调查保留原始证据。

动作保留的恢复入口主要风险
输出落盘实际路径与行号范围路径无效或文件被清理
历史裁剪近期原文与完整 transcript丢目标或切开调用结果配对
旧结果缩减结果来源说明后续需要细节却无法找回
模型摘要约束、进度、精确标识有损改写与错误累计

课程用字符串大小做近似时，阈值不是精确 token。保留 transcript 也不表示已有自动检索能力，模型是否能够重新读取还需要工具与路径支持。

s09 · 长期记忆有读、写、整理三条路

长期记忆可把“该项目统一使用 UTC”与“这次临时不运行联网测试”区别处理。前者有来源和长期适用范围，后者应保留在任务记录，不宜升级为所有未来测试都离线的用户偏好。

读取相关记忆、写入候选、整理去重是不同操作。更新冲突时保留有效期与原始出处，索引文件指向细分记录，不把所有日志塞进一个常驻 MEMORY.md。

s10 · 提示词是运行态配置

提示应随启用工具、目录、记忆和项目约束组装。确定性序列化可检测这些依赖是否变化，只有依赖相同时才复用字符串；工具集合改变却不失效，会让模型看见陈旧能力。

本地提示字符串缓存节省拼装，供应商前缀缓存可能节省推理开销。两者计量与失效不同，不能用本地 hit 统计宣称模型账单已经下降。

s11–s14：错误、任务与时间

错误恢复、任务恢复和调度恢复属于三类时间问题，各需对应状态，不能靠统一重试补救。

s11 · 先分类，再恢复

故障合适恢复本任务的风险
响应输出不完整有界续写或调整输出预算不能把半份修改说明当测试通过
输入过长缩减上下文后再请求原样重试只重复失败
暂时限流退避、抖动与总时限避免多个队友同步重试
无效参数修正或终止等待不会修好错误路径

扩大输出额度要在模型支持和费用预算内。模型请求重试与工具重试分开处理，已保存的文件、已发送的通知不能因为上层 API 失败就无条件重复。

s12 · Todo 升级为可恢复任务图

任务图把“补跨日测试”依赖“明确 UTC 规则”，“核对展示”依赖“解析返回结构”写成 blockedBy，记录 owner 和状态到 .tasks。重启能找回定义，却仍需核对文件与验收是否真实存在。

教学依赖检查不必包含环检测，A 等 B、B 等 A 会停住。并发认领若没有原子条件更新仍可重复，独立 JSON 文件不是自动事务队列。

s13 · 后台任务需要第二种通知

慢测试后台运行时，原调用立即返回任务 ID，完成后独立通知含退出码和日志路径。不能给原 tool_call_id 再塞第二份工具结果，否则破坏请求配对。

后台等待期间可处理无依赖工作，但任务完成前不得宣布验收通过。轮询也有预算，等待操作系统进程本身不消耗模型 token，反复问模型“好了没有”才会增加调用。

s14 · 定时器只生产任务

调度器到时生产任务，队列处理器在合适时机交给 Agent。把定义写盘可以重启后恢复计划，不表示进程退出期间仍在执行。系统级 cron 或常驻服务属于另一层部署责任。

对每日校验任务，需定义错过触发时补跑还是跳过，并用日期或批次组成幂等键。仅保存“每天运行”不足以解释重启后的重复行为。

s15–s19：从委派到团队

团队机制扩大并发面，也扩大了消息、文件和任务状态的竞争窗口。

s15 · 有邮箱，才有长期协作

Lead 与长期队友通过邮箱通信，比一次性子 Agent 更适合多轮配合。新任务中一人跟踪解析器，一人检查展示，两边传递证据与接口约定，而不是互发“我已完成”。

JSONL 邮箱若采用读后删除，可能与写入竞争。严肃并发需锁或可靠消息队列，并为消息定义 ID、确认和重复处理规则。

s16 · 关机和审批都是请求 / 响应协议

关机、计划审批都应带 request_id 并核对响应类型。队友回复“同意关机”不能误当批准解析规则变更；过期响应也不能批准新任务。

课程 s16 展示请求与响应协议，不代表每条写文件和 bash 都检查了批准状态。若要强制“未批不得写”，必须在真正工具执行前读取当前审批并核对范围。

s17 · 自治认领不是不受控制

队友先处理取消与关机等控制消息，再找依赖满足、无 owner 的任务，成功认领后执行。没活可等待后退出，不能空转无限调用模型。

读到 owner 为空并非认领成功，写入 owner 后也不证明没有竞争。应以原子认领返回值为准，并记录租约或进程失联后的接管规则；这些属于教学版之外需核对的能力。

s18 · Worktree 隔离改动，不隔离操作系统

不同 worktree 可以让解析器与界面改动分别审查，工具 cwd 指向对应目录。完成后保留差异供合并，清理前核对未保存产物与用户改动。

worktree 不隔离网络、环境变量、进程或数据库。两个目录若都写同一个本地状态库，仍可能冲突；最终合并也需要测试，不能因各自通过就推断组合必然正确。

s19 · MCP 接入的是工具协议

MCP 客户端发现服务工具，添加命名空间后放进模型工具池，再分发调用。课程模拟 handler 展示发现和分发，不是真实 stdio 或 HTTP 协议测试，且不一定给每位队友相同工具集。

readOnly 或 destructive 的说明是元数据，执行侧仍要落实路径、身份与审批。外部工具返回的不可信文字也不应提升成项目指令。

s20：把登录修复串成一个闭环

综合演练围绕本章新任务完成。固定输入包括空时间、UTC 跨日与显式时区三类假报文，验收规定空时间返回缺测状态，不得写当前系统时间。

  1. 准备阶段先保存规格、禁止事项和三类验收，分成解析与展示任务，明确接口依赖。需要隔离时使用练习工作区，正式数据保持只读。

  2. 执行阶段加载相关技能，工具前校验路径与审批，输出过大先落盘。两个队友在各自任务范围修改，测试作为后台任务返回 ID。

  3. 反馈阶段接收测试通知，跨日失败的日志成为新观察。限流与参数错误走不同恢复，用户取消优先进入控制路径，不排在普通工作后面。

  4. 收尾阶段核对测试证据、任务依赖、后台进程和队友关机响应。报告写明已验证与未验证项，保留待审差异，不把存在完成标记等同产品验收。

这些是组合后的验收要求，课程综合代码是否逐项实现，需要逐条对照。没有生产沙箱、可靠队列或原子认领时，应明确已知限制。2

四个问题检查你是否真正理解

工具前钩子看到了审批请求，为什么仍不能执行？

请求存在不等于已批准。要核对当前响应、类型、有效期和参数范围，并在执行前再次确认。

测试日志已经缩成摘要，怎样找回原始失败？

先查大输出落盘路径和任务 ID。若只留摘要没有原文，就应承认细节已丢失，必要时重跑离线测试。

JSON 任务文件存在，为什么定时任务没运行？

文件保存定义，活进程才推进调度和执行。还需检查到期规则、常驻服务与停机补跑策略。

新增工具后模型仍不调用，先检查什么？

检查真实工具池、提示失效和新能力是否进入当前请求，再区分模型选择与宿主未加载，不能只看配置文件内容。

来源与适用范围

本章对应 s01 至 s20 中文讲义和相关实现，压缩与综合机制按对应课程追溯。时间解析修复、假报文和验收为新设计，未启动队友、MCP 服务或后台测试。展示网站与翻译材料不另构成新的执行能力。
