四层学习地图

“能做一个质检助手”包含不同层次的工作。读懂一次模型请求、限制工具、管理长任务和解释训练目标都重要，却不必一次学完。可以用一份能力证据表记录自己已经验证的部分，按当前任务缺口选择阅读，而非只统计读过多少章。

Foundation

Capability

行动能力关注模型如何在新观察后改变路线。给 B17 一条空记录，观察它是澄清时间范围、换证据源还是编造数值；需要分工时检查角色之间是否保留证据。相关材料集中在 01 至 03 与 08，验收单位应是完整轨迹。

Runtime

运行能力关注长时间与多请求：历史保留、权限、任务状态、预算和恢复。一次正确回答不足以证明本层完成，可以加入重投递、取消、重启和越权输入。07、09、10 及真实运行时章节提供不同实现入口。

Model

仓库学习路线

概念阅读后再精读实现，容易区分“必须满足的机制”和“项目的某种选择”。比如记忆需要有效读写，但每轮重建 system 或会话冻结只是两种策略；先知道这个差别，再看源码才不会把一套实现当成全部答案。

按任务缺口安排的阅读路径
一条观测查询：01 调用 → 02/03 行动与规划
资料有出处：04/05 检索 → 06 验收
跨班次持续：07 记忆 → 09/10 约束与状态
实现对照：08-hermes-agent → 12-hermes-agent-small → 13-pi-agent
长期维护：09 Loop 材料 → 10 CI/CD 材料 → 11 LangGraph 材料
模型疑问：07-llm_from_scrach 按具体计算问题回查

编号在这里是仓库目录，不等于电子书章节号。阅读计划应标明正在查目录还是章节，以免将 08-hermes-agent 误当第 08 章。00-大纲/ 提供主题顺序，99-My idea/ 提供研究线索，两者都是入口，不能代替源码行为证据。

每次精读只跟一条链路：比如一条记忆从写入到下一轮可见，或者取消如何传到工具进程。写出入口、状态变化与出口后，再扩到相邻模块，避免在一堆目录间跳转却没有追完一个对象。

记忆的三个补充视角

浮标助手的记忆问题可以拆成容量、冲突和恢复三类。不同存储技术主要解决其中一部分，不能只因为接了向量库就认为长期记忆已经完整。

四层递进的内存体系

层次保留内容适用限制
Conversation History刚刚读取的报文与用户追问窗口有限，早期约束可能离开上下文
Working Memory本轮设备、时间标准、未完成项需小而精，不能塞入全部日志
Semantic Recall相关标定讨论与稳定约定召回需过滤身份、时间和版本
Observational Memory长会话中提炼的观察与事件抽取、遗忘和溯源策略都要另外验证

这套分类与 Hermes 的具体四层实现不是一一对应关系。前者按记忆用途划分，后者按文件、全文索引、外部服务与技能组织；同一个 SQLite 库也可以保存多种用途的数据。

记忆是一个闭环：Write → Reconcile → Read

教学场景中，B17 在 06 月 01 日前使用标定版本 C2，之后换成 C3。写入新记录后，调和步骤应给旧版本补有效结束时间，并保留来源；查询 05 月数据仍应取 C2，查询 06 月 03 日则取 C3。如果直接覆盖成“B17 使用 C3”，历史重算会错；如果把两条事实原样并列，模型又可能随意选择。

因此闭环至少包含候选写入、冲突识别、有效期与来源管理、按问题读取、过期或删除。写入失败与尚未确认的推测应分开状态，不能把一次工具错误永久保存成设备属性。调和可以由规则、人工或模型辅助，但最终结果需有可追查依据。

长对话摘要丢信息怎么办

长对话压缩前，将不可违反的条件放到结构化工作记忆，例如“原始报文只读”“仅处理 B17”。旧讨论分段摘要，细节留在带编号的原始记录；当前问题需要时再检索。若摘要写成“数据已修好”，后续恢复必须检查磁盘和测试，不能把省略细节误当验收完成。

情节蒸馏为稳定事实还要过筛：一次临时要求“这一份报告用本地时间”不应自动变成永久偏好。waku 的读门控决定是否召回，批量巩固决定何时抽取，二者有关但不是同一项筛选。应分别测漏召回和错误沉淀。

Agent 评测的特殊性

两个助手都正确指出缺测率为 8.33%，仍可能有很大差别：一个读了授权的 72 个时槽，另一个读错设备却碰巧得到相同比例。Agent 评测需要检查动作与环境状态，不只比较最后一句数字。

维度教学测量项应一起报告的条件
能力计算与解释是否正确题集、金标和判定规则
可靠性重复执行、失败恢复与超时率重试、预算和每题运行次数
成本模型调用、token、工具等待模型版本与计价口径
安全越权读取、未批外发、跨组串记忆身份、权限和环境隔离

教学数据里，A 在 20 题中通过 18 题且没有越权，B 也通过 18 题却有 2 次未经批准发送。若只报 90% 会掩盖业务不能接受的差异。应保留逐题轨迹、失败分类和副作用结果，聚合指标只是索引。

复现还需固定模型、工具版本、记忆初始状态、会话边界和外部数据。第一次运行留下的记忆可能帮助第二次，若不重置或明确报告，就不是相同条件。mock 用于验证控制流，真实模型用来测概率行为，两种结果分别标注。

AI Coding 工作流

让编码 Agent 修改浮标解析器时，任务说明、实现和验收应围绕同一条数据路径。需求是“空温度保留缺测”，测试必须覆盖空字符串与合法 0.0；只运行语法检查无法证明语义正确。

两个奇怪的约束

研究笔记中的 Smart Zone / Dumb Zone 提醒读者控制上下文噪声，但某个窗口百分比并不是所有模型统一的能力阈值。注意力计算规模随序列长度增长，也不能直接推出超过 40% 就必然变笨。模型、任务、证据位置和提示结构都会影响表现，应把这条说法当成待测启发。

清空会话会丢失隐含进展，摘要则可能引入误述。可从明确计划、代码和测试重建状态时，阶段边界重开较容易复现；进行中的调查还需要未完成项与证据路径，则应提供经过核对的交接。Clear 和 Compact 都需要检查哪些状态只存在于上下文，不能按口号选择。

端到端工作流

Issue 应是一块可验证的小改动，而不是把整个助手需求换个名字。自动检查先过滤语法、类型和固定契约，人审再核对缺测语义、数据授权和未覆盖风险。AFK 实现仍要有时间、轮数和工作区限制，不是把正式岸站交给无人约束的循环。

面试口述要点

口述技术方案时，可以从 B17 的一个具体故障展开：读到空温度后怎样处理，为什么需要标定信息，何时暂停等人，怎样避免重复外发。这样的回答能把抽象名词连接到状态和证据。

追问应说明的机制可回查章节
工具报错之后怎么办错误观察、分类恢复和预算01 至 03、09
如何判断回答有依据候选召回、断言支持与版本04 至 06、20
多人讨论怎样不串记忆命名空间、会话键与权限过滤07、14、24
批准后重启怎样继续检查点、请求匹配与幂等16、17
长期循环如何结束完成证据、预算和取消10 至 12、22

如果还没有真实项目经历，可诚实标为教学练习，讲清构造输入与观察结果。不要把纸上设计包装成已经稳定运行的产品；对失败边界的解释通常比一串框架名更能说明理解。[2]

如何继续学习

继续学习可以围绕一个小而真实的只读需求，例如每个值班日生成“缺测、异常候选和待确认项”。先限制数据范围与输出，不急于接设备写操作。这样能在有限预算内看到完整周期。

实现线从一个固定输入的统计工具起步，再加检索和报告；源码线选 Hermes 的一条完整记忆路径，与 waku、Pi 做责任归属对照；基础线在需要时补异步、数据库事务、模型计算与 CI。三条线共享同一验收样本，避免学习成果互不相干。

当系统运行一周后，记录题目分布、未知结论、恢复次数和人工修订原因。用这些实际失败决定下周读什么，而非追逐最新框架。学习笔记应把结论连到版本、数据和命令，旧结论失效时更新证据入口。[1]

延伸对照：把笔记连回主线

把研究笔记转成可验证问题，能避免将观点原样写进技术决策。下面每一项都有可能被反例推翻，因而适合作为下一轮实验入口。

笔记主题可检验问题需要的证据
能力层次模型强但工具权限错时是否仍危险相同任务的动作轨迹
记忆闭环新标定是否污染历史重算不同日期查询结果
摘要压缩只读约束在多次压缩后是否保留恢复后工具请求
上下文预算噪声与证据位置怎样影响判断同题不同上下文的重复试验
编码工作流新会话能否仅凭交接继续重开后的实现与验收记录

这些问题分别连接 07、10、11、16 与项目补编。00-大纲/ 和 99-My idea/ 可提供线索，但最终判断仍应回到实现和可重复观察。不能把研究笔记出现过的能力都记成仓库已完成。

动手验证

练习不需要真实服务，可用纸上状态表或脱敏的本地记录完成。

练习一：用四层地图自测

给四层各列一项可展示证据：正确工具回填、异常后改路线、重启后恢复、解释 KV 缓存。再各加一条会让结论失败的输入。只有正例而没有反例时，往往还没明确能力边界。

练习二：做一次记忆冲突处理

为 B17 构造 C2 与 C3 的有效期和两条观测日期，分别查询应使用哪个系数。加入一条来源未确认的 C4，说明为什么不能只按最新写入时间覆盖已批准记录。

练习三：计算你的 Smart Zone

在一组固定质检题中逐渐加入无关日志，保持关键证据内容不变但改变位置，记录准确率和输入长度。把所谓 40% 经验线当待比较条件，不将单次失败归因于某个普适百分比。没有模型环境时只写实验设计与判定标准。

练习四：写一份诚实的评测报告

为两个助手写评测表，至少含每题结果、工具越权、步骤数、总 usage、失败恢复与是否外发。给二者相同通过率但不同安全表现，解释为何不能只给一个排名。

回顾与自测

学习地图有用的前提是可以回到证据。记忆必须能解释有效期，评测必须能解释运行条件，交接必须能让新会话继续，而非只展示一份漂亮提纲。

读源码前需要掌握到什么程度？

至少能描述一次请求的模型、工具、状态与验收边界。随后通过源码修正理解，不必等学完所有概念才开始。

相同通过率还能比较什么？

错误类型、越权和外发、重试次数、成本、时延与恢复结果。相同答案比例可能对应完全不同风险。

新会话和摘要哪个更可复现？

取决于外部状态是否完整。能从规格和产物重建时新会话较直观；否则需要核对过的摘要与证据。两者都不能忽略磁盘与副作用。
