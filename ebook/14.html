从一个循环到一套运行时

值班员在终端问 B17 的温度突降原因，稍后又在群里发来“把刚才那份报告发给夜班”。如果两处入口各自实现一个循环，历史关联、权限与记忆很快出现分歧。定时巡检还可能同时处理同一设备，产生重复报告。把模型调用写通之后，还需要有人管理这些请求的身份、先后与持久状态。

08-hermes-agent/ 保存 Hermes 的架构讲义、摘录和教学 demo。它适合追踪从入口到 AIAgent 的共同路径，以及循环周围如何装配提示、记忆、执行环境和后台任务。本章使用浮标质检的新任务解释机制，不声称原项目已经具备浮标协议解析器。

建议为一次请求建立三份记录：用户期望完成什么，模型实际看见什么，程序真正执行什么。报告文字、工具观察和磁盘状态可能不同步，只有同时查看三者，才能解释“已经记住”为什么暂时没有进入下一次模型请求。

窄腰架构

这张责任分配图以一个观测请求为单位。不同入口可以携带不同元数据，但推理和工具回填的语义应保持一致。

多种入口

AIAgent 窄腰

边缘能力

工具实现可替换的读取、计算和输出；技能描述如何组织质检步骤；记忆 Provider 负责外部存取；平台适配器负责投递。核心使用这些接口，但不必知道每个传感器型号。增加新数据源时，应检查工具契约和身份隔离，而不是复制整套 run_agent.py。

Agent Loop

一次用户输入可能触发多次模型调用。教学任务是比较 B17 两个时段，第一次请求先读原始记录，第二次调用计算差值，第三次才给报告。每个工具观察都要与发起它的调用编号配对，否则下一次模型请求无法确定某个数值来自哪次读取。

质检请求的教学轨迹
用户：比较 B17 的两个观测时段
上下文构建 → 模型请求 read_records
读取结果   → 写入对应 tool message
模型请求 compute_delta → 写入计算结果
模型给出最终说明 → 保存会话 / 回合收尾同步

主动 memory 工具：可在工具迭代中发生
外部 provider 同步：按回合生命周期处理

不能把所有写记忆行为都放在图上的最后一个箭头。模型可以主动使用内置记忆工具；外部 Provider 的 turn 同步属于另一条路径；后台复盘也可能提炼稳定经验。上下文构建主要读取当时可用的状态，不会提前知道尚未完成的分析结论。

若读取工具超时，宿主应返回可识别的错误观察或终止状态，而不是伪造零值。最终回答自然结束只表示模型不再请求工具，是否已完成质检还需核对数据范围、缺测率与证据引用。循环终止和业务验收是两个边界。

Session、Turn 与 Context

这里沿用讲义的术语：Session 是持续对话容器，Turn 是一条用户消息及其完整处理，工具往返发生在 Turn 内。不同项目会用不同粒度命名 turn，跨系统对照时应先写出边界，不能仅凭同名字段推断计数相同。

Session 启动

每个 Turn

假设值班员改为“以后同时显示开尔文”。本轮可通过工具返回新记忆的 live 状态，因此能在这次回复里采用新要求；但此前构建的系统前缀不会因为文件写入自动变成新版本。讲义描述的缓存策略把启动快照保留在 Session 内，压缩重建等特定边界才会重新组装。[1]

检查上下文超限通常发生在请求边界，错误恢复也可能触发压缩。压缩改变活跃提示视图，不应被误认为把磁盘原始历史全部删除。不要依赖固定前缀承担紧急权限撤销，执行侧仍必须读取有效授权。

Session 结束

新 Session 启动时再读取更新后的记忆。旧会话可以保留已冻结的上下文，用于解释当时为何作出某个回答；需要立即采用新事实时，应明确启动新会话、重建上下文或在当前轮提供权威更新，而不是反复写同一文件并期待缓存自行失效。

Prompt 的三层缓存

提示词先按用途分开：面向主模型的系统前缀、执行窄任务的辅助调用、当前用户轮的动态注入。辅助摘要器的指令不应该被当作质检 Agent 永久人设，某轮检索的设备维修记录也不应直接覆盖系统约束。

系统前缀层浮标助手中的教学对应变化会影响什么
stable身份、工具协议、技能目录、环境说明靠前变化会使较长前缀不再复用
context岸站项目说明、调用方约束不同项目应有不同上下文来源
volatile记忆块、时间等会话相关材料易变部分放后，减少对前段的干扰

这三层的名称描述内容稳定性，不表示每一层都在每轮重新渲染。讲义中的 Session 策略仍会冻结组装结果。服务商前缀缓存、本地字符串缓存和实例复用也不是同一种缓存：组装字符串未变，不代表供应商满足最小缓存长度、有效期或命中条件。

判断缓存问题时可保存脱敏后的层级摘要与内容 hash，比较从哪一层开始变化。不要为了追踪命中把完整用户记忆写入公共日志。当前观测时间若每秒改变，且位于前缀开头，会让后面的相同说明失去复用机会；它应处在变化区域，或按实际业务粒度更新。

记忆四层体系

浮标助手需要同时处理少量固定约定、过去对话、跨会话关系和领域资料。Hermes 的记忆层可以叠加，不要求接入外部服务后抛弃本地文件。

层次适合存什么不适合承担什么
Markdown 常驻记忆报告单位、稳定用户偏好每十分钟一条的完整传感器流
state.db 与 session_search按关键词回看历史讨论保证业务事实当前仍有效
外部 Provider相关经历召回、身份建模等可选增强自动替代访问控制与授权
Obsidian Skill较大领域库的组织与访问流程每个会话无条件加载全部资料

比如“报告默认使用 UTC”值得常驻，而“昨天 B17 曾断链”应带事件时间和来源，只有相关问题才召回。存储记录存在不代表仍然适用；一次暂时故障也不能升级为设备永久属性。

外部接线可沿抽象 Provider、Manager 注册、回合预取、注入、收尾同步及提示约定逐项查看。Mem0 这一类服务承担后端存取，Manager 管生命周期与结果边界。检查时应另外确认设备、用户与会话如何映射到后端命名空间，某个 Provider 超时是否影响其他结果，以及中断轮次哪些信息允许写入。

执行环境

模型请求运行统计脚本时，真正读取文件的是 terminal 工具背后的执行环境。Local、Docker、SSH 或云沙箱可以对外返回相似的输出与退出码，但各自能看见的数据、进程与网络不同。工具接口一致并不意味着权限相同。

教学路径定位
terminal 请求：统计工作区内 records.csv 的缺测数
  → terminal_tool 读取环境配置
  → 创建或复用 environment
  → environment.execute(command)
  → 返回 output / returncode
  → 宿主按工具调用编号写回观察
# 路径相同不代表文件相同，需核对后端挂载与 cwd。

若本地有 records.csv，远端工作区却没有，正确现象可能是文件不存在，而非脚本算法错误。排查先记后端、工作目录和路径映射，再看命令。隔离目录不等于沙箱，容器挂入宿主敏感目录也会扩大暴露面。

取消与超时还需要检查进程是否退出、临时文件是否留下、后端是否清理。这里的 Env 负责命令执行位置，Runtime 则负责整个会话、队列和模型循环；替换 Env 不能自动替换这些产品行为。

Cron 与 Gateway

岸站希望每天 08:00 汇总前一天缺测情况。Cron 保存的是何时发起工作、执行什么以及把结果交到哪里。讲义中的任务定义位于 jobs.json，常驻 Gateway 周期性检查到期项，可以启动 Agent 回合或运行脚本，再把结果保存到 cron/output/ 并按配置投递。轮询周期描述发现到期任务的节奏，不是严格准点的实时保证。

Gateway 的入站路径把平台消息统一为 MessageEvent，按会话键恢复历史，再复用对应 Agent。这样同一值班组的连续讨论不会每条消息都失去前缀与历史。不同组、不同用户的会话键若设计错误，则可能出现跨组记忆泄漏，不能只用设备编号作为所有请求的会话键。

运行中的普通消息可以排队，停止、批准、拒绝和澄清这类控制消息却需要及时抵达。Adapter 和 Runner 都有忙时守卫，必须在两层识别控制路径，否则正在等审批的 Agent 会永远等不到被排队的批准。绕过忙队列仍需鉴权与请求匹配。平台重投递也需要幂等处理，避免同一份日报发送两次。[2]

Eval 在主循环之外

用户等报告时不宜再串上一套完整离线评分。运行时产生消息、工具观察和日志，评测读取已经保存的轨迹。权限审批则仍在执行前发生，不能因为“评测放旁路”就把权限门也移到事后。

热路径

旁路观测

API 与工具 span、会话标签、错误日志提供定位入口。一次工具失败可能属于读取路径而非生成路径，Trace 的父子关系能显示错误传播。观测输出应限制敏感内容与体积，不能把每条原始浮标报文默认送到外部平台。

事后评测

教学 demo 把 pytest 契约断言与 run_eval_suite.py 的规则评分、RCA 分开。可以给它一条正确轨迹和一条工具编号错配的故障轨迹：前者通过，后者被检出，才说明规则有区分能力。离线不需要模型密钥的部分验证的是这些契约，不能据此宣称在线回答质量或服务可用率已被测过。

状态落盘

文件分工决定备份与恢复能否解释清楚。人格、记忆和会话是不同状态，恢复一个旧文件可能让它们处在不同版本。

位置用途维护注意
~/.hermes/config.yaml行为配置升级时检查字段兼容
~/.hermes/.env凭据配置位置不应纳入可公开的会话导出
memories/ 与 SOUL.md稳定信息和人格说明区分文件版本与当前提示快照
cron/jobs.json计划定义恢复前检查时区、收件地址和重复执行
state.dbtranscript 与全文索引数据库备份需遵守 SQLite 一致性要求

Profile 通过独立 HERMES_HOME 隔开多套状态，但共享的远端服务、宿主目录或操作系统账户仍可能跨 Profile 可见。Windows 原生目录与 WSL 的家目录也不同，迁移时应明确实际使用的根目录，不能把看到两个目录直接理解成数据丢失。

延伸对照：真实 Agent Runtime 的公共课题

把 Hermes 当成一种实现来比较，可以区分普遍约束与项目选择。固定前缀属于成本策略，身份隔离则是任何实现都必须明确的安全要求。

记忆与上下文

MemGPT 提供上下文与外部存储调度的研究视角；Mem0 关注可复用事实的提取与管理；Zep 可用于思考时间关系。对浮标助手而言，需分别验证“记住默认单位”“找到上次断链讨论”“知道当前标定有效期”，这不是同一个召回测试。

执行环境与接口

SWE-agent 的接口研究提醒读者，工具输出怎样呈现会影响后续决策。观测读取工具若只回一堆无时间戳数字，模型很难正确比较两个时段。MCP 可统一连接协议，但设备访问权限、时间范围校验与副作用控制仍属于工具实现。

可观测与评测

待判断问题所需材料不可混用的证据
提示前缀变了吗层级内容 hash 与组装版本实例复用不等于服务端缓存命中
工具调用正确吗结构化参数和结果配对最终回答顺畅不等于调用正确
报告可靠吗实际证据、标注题与逐题评分离线契约通过不等于模型质量通过

一个可迁移的设计原则

稳定核心与可替换边缘之间要有足够明确的契约。比如更换报文读取后端时，要求返回相同时间标准、缺测表示和错误类型；若新后端把空值改成 0，就算接口仍返回 JSON，核心也会作出错误结论。接口稳定包括语义稳定，不只包括函数签名。

动手验证

练习以脱敏假数据为输入，先做接线检查，不要求连接聊天平台或外部记忆服务。

练习一：拆一次 Context 组装

阅读 04-prompt/notes/1_assembly_map.md，把“默认 UTC”“B17 本轮缺测”“报告工具 schema”分别放入适合的位置，说明哪些属于稳定约定、哪些只属于当前数据。给一次组装结果编号，再模拟文件更新，标出当前会话哪些区域会变化。

练习二：跟一条 Gateway 消息

参照 08-gateway/notes/1_message_pipeline.md，画出群消息的发送者、会话键、消息 ID 和投递目标。构造两个群同时讨论 B17 的情况，检查它们是否仍保有独立历史。若将消息 ID 重投递一次，指出哪里应阻止重复运行。

练习三：跑一次离线 Eval

在 03-eval/demo/ 检查测试和评分入口，选一条工具配对错误的 fixture。先预测会由哪层检出，再选择是否运行。记录契约退出码和规则报告，不把故障样例被判失败误记为评测器损坏。

练习四：追踪一次记忆写入

沿 07-mem-provider/ 写出预取、注入、生成和收尾同步的顺序。让用户在工具执行后中断，分别标记原始历史、稳定偏好和未完成推测是否允许保存，说明中断处理依据哪一个实现分支。

回顾与自测

检查 Hermes 中的一条质检请求，应能分别定位入口身份、当前会话视图、实际执行环境和事后评测材料。它们共用任务关联信息，但不应互相冒充。

记忆更新成功，为什么报告仍沿用旧单位？

查看写盘版本与当前系统提示快照，再查本轮是否有 live 返回。磁盘写入本身不会自动修改已经提交给模型的消息。

评分器离线运行，是否可以省掉执行前权限检查？

不能。事后评分只能发现问题，无法阻止已经发生的文件写入或外发。权限属于执行前控制。

新增一个消息平台要重写什么？

主要是事件规范化、授权与投递适配。共同循环与工具结果配对应复用；平台特有的重投递和会话规则仍需测试。
