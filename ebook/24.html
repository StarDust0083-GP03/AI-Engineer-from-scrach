Hermes 不是只有一个 while 循环

值班员说“从明天起把缺测单列，不并入异常数”，随后要求检查 B17 的夜间观测。助手可能更新本地记忆、查询外部 Provider、调用终端统计，再把草稿投递到值班群。每个动作发生在不同边界，不能只画一个 while 就解释全部行为。

08-hermes-agent/ 的专题目录分别放大这些接线。本章按消息生命周期重新组织教学任务，保留源码与目录事实，不使用旧偏好案例。各处 hermes_src 和 hermes-study 是只读摘录或剪枝学习副本，依赖未必完整；若 demo 要求 HERMES_AGENT_ROOT，需指向仓库外正确版本源码，不能把摘录直接当安装包。1

阅读时可给所有事件标上会话 S21 与本轮 T4，同时区分调用 ID 和后台任务 ID。前者解决工具结果配对，后者解决跨时刻任务关联，不能拿同一个无类型字符串随意混用。

把热路径和旁路分开

把用户等待的工作、后台产生的工作和离线检查分别列出，可以判断一个耗时操作究竟延迟了谁。

01、02、07：一轮对话里的记忆读写

记忆读写要看保存对象和生命周期，不能把所有路径合成“每轮自动记住一切”。

Session、Turn、工具迭代不是同一层

S21 包含多条用户消息，T4 是一次输入与回复，其中可能读取报文、运行统计和保存草稿三次工具。工具里的中间猜测不应每一步都进入稳定事实，比如一次统计失败不能被存成“B17 没有数据”。

内置 memory 工具、外部 Provider 收尾同步和后台复盘是不同写入口。主动写入可以在工具迭代里发生，收尾同步则按回合与中断规则处理；后台整理另有触发。区分这几条路径才能解释为什么某项信息已落盘，却还未出现在当前提示里。

读取分为两条路

常驻 MEMORY.md / USER.md 及 Provider 系统块可进入系统提示快照。与当前问题相关的外部记忆则经 turn 开始预取，由 Manager 汇总后放入有边界的 memory-context 数据区，再附到本轮消息。动态检索不必改动稳定前缀，但记忆里的指令仍应当数据看待。

“缺测单列”是稳定输出约定，“本次读取 B17 的 02:00 至 04:00”是当前任务范围，二者生命周期不同。召回时保留用户范围、来源与时间；只有文本相关而身份不符时仍不得注入。

用一个偏好走一遍

  1. 用户提出新统计口径，系统按允许路径保存“缺测不计入异常”。当前回复可以通过实时工具结果确认保存，不假定冻结前缀已刷新。

  2. 下一轮要求统计夜间情况，Manager 对启用 Provider 预取相关信息，返回带出处的口径记录。

  3. 工具分别统计缺测与异常，模型在说明中明确两者分母和集合。不能只换栏目名称却仍把缺测计入异常数。

  4. 回合结束后同步允许保存的新信息。若用户中途取消，应按实现跳过不应保存的未完成结论，同时保留必要的运行记录。

Mem0 接线展示一种外部后端，Honcho 学习副本展示另一种组织方式。Manager 管注册、扇出、围栏和会话生命周期，Provider 管具体存取。更换后端仍需检查用户映射、超时、重复同步和删除语义，不能因接口相同就推断数据治理相同。

02 主循环为什么拦截 Todo

Todo 与当前 Agent 的可变任务状态密切相关，可能在 Agent 层直接处理，而非像普通无状态函数一样经统一分发表。这不破坏模型可见工具协议：对模型仍是有名字、参数和结果的能力，只是宿主分发位置不同。

核对主循环时应找出 Todo 的持有对象和生命周期，确认它是本轮临时提醒还是跨重启任务。模型把 Todo 写为 completed 不会自动验证统计脚本退出码，运行时仍需保存真实证据。

04：17 份 Prompt 目录，归成三类就不乱了

17 份目录条目可以按主模型前缀、辅助调用和用户轮注入三种去向理解，而非按文件数量推断有 17 个 Agent。

去向目录主题在新任务中的作用
缓存前缀宏、组装、编码与验证指导定义稳定身份、工具和工作约束
辅助调用压缩及教学/运行时摘要、标题、Curator、MoA压缩统计过程、为会话命名或整理经验
辅助调用Goal/Judge、需求、看板、Profile、视觉完成专门输出，不自动进入主工具循环
当前轮注入后台复盘、技能回顾、/learn在指定时点发起经验整理

假设统计轨迹变长，摘要器读取历史并保留“缺测单列”的约束；标题生成器只产生简短会话名；/learn 则可能把重复的核对方法整理成技能。它们虽然都可调用模型，输入、权限和结果去向却不同，不能把所有 usage 算成同一轮主推理的步骤数。

本地缓存组装字符串、复用 AIAgent 实例和服务端缓存前缀是三种机制。任何一层命中都不保证另外两层命中。调试时分别记录内容版本、实例生命周期和供应商 usage；更新规范时还要保证生效路径，不能为了缓存永久沿用旧口径。

05：工具命令到底在哪台机器执行

终端工具接收“运行缺测统计”时，环境后端决定读的是船载工作站还是远端目录。LocalEnvironment 通过本机进程执行，Docker、SSH、Modal、Daytona、Singularity 等有各自的资源与文件边界。相同 execute 接口不等于相同权限和路径视图。

local demo 的 echo、pwd 等命令用于认识初始化、执行与清理，不证明任意命令已在安全沙箱内。新质检任务更需要核对输入 CSV 是否只读挂载、输出目录可写、模型与脚本是否继承多余环境变量。这里只说明配置位置，不读取任何真实凭据。

后端新任务的核对对象常见误判
Local用户权限、cwd、可见文件和子进程隔离目录就等于权限隔离
容器或平台环境挂载、网络、特权与资源上限名字叫容器就默认无法访问宿主
SSH远端账号、路径映射和连接状态本地同名文件就是执行输入

工具返回 timeout 只说明等待结束，仍应确认统计进程和孙进程是否停止，临时文件是否留下。取消处理如果只改变 UI 状态，后台脚本可能继续写输出。完整验证需观察实际资源状态，而不是看一条“已取消”提示。

06：定时任务从创建到投递

把“每天 07:30 检查前日缺测”变成任务，至少需要时区、数据范围、执行分支、接收目标与错过触发策略。定义不完整时应澄清，不由模型自行猜值班组。

  1. cronjob 创建后将计划写入 HERMES_HOME/cron/jobs.json。持久定义与正在执行的实例分开记录。

  2. scheduler.tick 获取相应锁，查找到期项；教学 demo 自行轮询，不依赖完整 Gateway 常驻。

  3. no_agent 分支直接执行脚本并收集输出，另一分支才创建 Agent。离线统计成功不能证明模型分支已运行。

  4. 结果保存到 cron/output 任务目录，deliver=local 只保存；需要远端交付时再走路由器。

原 demo 每分钟和固定次数的安排是教学配置，实际新任务不必照搬。立即到期的调试开关改变等待行为，应单独说明；RUN_AGENT 默认关闭时尤其不能把脚本执行当完整对话测试。

Cron 在材料中跳过某些常规记忆路径，避免自动化过程污染用户画像。是否需要记录“前日统计已完成”应放任务结果而非长期人格记忆。发送重试要有批次键，不能每次 tick 都重复生成同一日报。

08：两道忙时守卫为什么都要给控制消息让路

平台事件带发送者、频道与消息 ID，归一为 MessageEvent 后按 Session Key 找历史，并缓存对应 AIAgent。不同值班群都讨论 B17 时仍应有独立会话，设备名称不能单独承担会话身份。

一个很容易发生的死锁

Adapter 的 active_sessions / pending_messages 与 Runner 的 running_agents / busy handler 都要识别停止、批准、拒绝和澄清，否则第一层放行、第二层仍排队也会卡住。绕过队列只提高控制优先级，不绕过身份验证、请求 ID 和当前状态检查。

取消若已完成的请求应返回明确状态，不能作用到刚开始的新请求。消息重投递还需去重，特别是批准和外发动作，不可靠队列中的一句文本无法承担全部协议。

为什么 Cron 不能“回复当前聊天”

后台任务发生时没有必然存在的“当前聊天”。Home channel 与显式 Delivery target 提供稳定目的地，origin 则保留创建时来源。若直接使用最近收到消息的地址，另一值班组恰好发来一条消息就可能收到错误报告。

应分别保存任务归属、执行会话和投递目标，发送前校验目标仍有效。投递失败不等于分析失败，本地结果可保留待重投，但报告状态不能提前写成已送达。

03：一份评测报告由两层证据组成

Layer A 用 pytest 检查契约关系，例如工具配对、压缩边界与缓存行为。Layer B 对固定正负轨迹检查工具序列、步骤、退出原因和不变量，并给出逐题分数与 RCA。这两层回答不同问题，不能只看最后一个总分。

新教学负例可以是把 B17 参数写成 B18，最终数值仍碰巧正确。契约或规则应检出设备不符，不能因文本回答看似合理就通过。另一个负例是在用户取消后继续调用保存工具，检验终止路径是否被观测到。

demo 可尝试读取主循环导出，否则用 fixture，并生成 session-tagged 日志。此处 JSONL 评分和 RCA 属于学习层，不表示 Hermes 主项目天然带有同名评测平台。故障样例被判失败是预期信号，把负例改成全绿反而使评测失去区分力。

脚本退出码可能主要由 pytest 决定，负例评分不一定使整脚本非零。因此报告应同时列契约状态、正例结果、负例检出情况与未执行项，不能把退出码 0 解读成所有业务质量都通过。2

09 与学习副本：不用图框架也有编排

研究快照中 Hermes 用自研模型与工具循环承载编排，说明不依赖图框架也能有会话、审批、队列和记忆。这个结论有版本范围，不应扩大成项目永远不会使用某个库。

比较术语时要比较语义：ToolNode 类似工具分发，checkpoint 类似保存执行状态，但 SessionDB 的对话持久化不自动具备任意节点精确恢复；审批可能只是进程内等待，也可能是持久中断，恢复边界需要具体检查。

群里已经回复批准，为什么统计任务仍在等待？

依次查 Adapter 与 Runner 队列、发送者权限、审批 ID、请求是否过期及回调是否被当前运行消费。先定位控制路径，不以模型“没有理解批准”作为默认解释。

每轮召回记忆放在数据围栏里就安全吗？

围栏有助于区分来源，但不能完全防止注入。仍需权限过滤、不把召回命令提升为系统指令，并在工具端执行真实限制。

可以纸上增加一次 Provider 超时、一次投递失败和一次跨组重投递，分别标出会话、任务与报告会留下什么状态。若这三种故障都只写“失败”，说明恢复信息还不够。
